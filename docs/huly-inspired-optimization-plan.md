# DooTask 优化路线图（参考 Huly）

## 目标与范围

以 DooTask 现有用户、数据模型、Laravel 后端、Vue 前端和 Electron 客户端为基础，逐步吸收 Huly 在任务依赖、项目规划、可配置视图、协作追踪和产品架构方面的成熟做法。先利用已有能力，再补真实缺口；每项功能都要考虑桌面端、移动端、权限、旧数据兼容、国际化和知识库说明。

本文是分阶段的实施计划，不代表一次性同时上线所有功能。优先级说明：

- **P0**：先做的基础调研、规则和设计。
- **P1**：核心产品收益高、适合先落地的能力。
- **P2**：建立在核心能力之上的效率增强。
- **P3**：长期体验、扩展性与工程质量改进。

## 当前基线：保留并复用

DooTask 已有较完整的协作和任务管理能力，路线图不重复建设这些功能：

- 任务看板、列表、甘特图、多条件筛选、按时间/状态等分组，以及项目排序和项目内显示偏好。
- 父子任务、周期任务、任务模板、通用任务关联、任务动态、任务交接记录和任务讨论。
- 可配置工作流、标签、项目成员与权限、部门负责人视角。
- 项目统计、个人/团队仪表盘、报告、文件、聊天、WebDAV、全文与语义搜索、AI 助手。
- Laravel migration、后端任务队列模式、API 文档映射、前端语言登记和 AI 产品知识库。

继续遵守 DooTask 的现有开发约定：新增跨模型业务逻辑放在 `app/Module/` 或 `app/Services/`；避免继续扩张冻结的大控制器；用户可见文案登记到语言源文件；功能/API/权限变化同步更新 `resources/ai-kb/`；所有数据库变更通过 migration。

## 分阶段实施

### 阶段 0：需求和数据边界确认（P0）

1. 画出项目任务数据流：任务创建/编辑、权限校验、动态日志、WebSocket 更新、甘特图缓存及搜索索引。
2. 核对现有任务模板是否保存子任务、负责人、日期、标签、工作流及跨项目复用规则。
3. 确认任务依赖的业务语义：首版限定同一项目、详情页暂不支持对子任务维护依赖；任务完成/删除后如何处理、手工排期与自动排期冲突时如何提示。
4. 定义里程碑是否允许跨列/跨项目，采用截止日还是日期区间，完成率按任务数还是权重计算。
5. 记录关键 API、权限范围、升级迁移、回滚与客户端兼容要求。

**完成条件：** 每项改动有明确的数据模型、API、权限、交互和验收标准；旧有通用关联与已保存偏好不会被破坏。

### 阶段 1：任务依赖与甘特图联动（P1，首个核心版本）

1. 将关系区分为“相关”“前置/阻塞”两类；已存在的任务关联迁移后默认保持“相关”。
2. 为依赖定义方向和关系类型；第一版优先支持常见的“完成后开始”（FS），再评估开始-开始、完成-完成、开始-完成及提前/延后天数。
3. 增加服务层校验：禁止自依赖、重复边和循环依赖；首版仅允许同一项目内建立依赖。
4. 任务详情展示“前置任务 / 后续任务”，可跳转目标任务；增加关联前选择方向的流程。
5. 甘特图显示依赖连线；在任务详情提供依赖编辑与移除入口；不能编辑时显示只读状态。
6. 记录依赖新增/移除和日期变化的双方动态；通知只发给相关成员，并按权限过滤内容。
7. 加入依赖开关或逐步启用策略，允许现有部署先只读/试用，再扩大使用范围。

**完成条件：** 旧关联显示和操作兼容；依赖方向一致；循环依赖无法保存；无权用户不能读取敏感任务标题或修改依赖；列表、详情和甘特图结果一致。

**当前进度：** 已实现项目级依赖开关、同项目主任务 FS 依赖表、权限校验、循环依赖检查、任务详情增删入口和甘特图依赖箭头；旧“关联任务”保持原样。关闭依赖后读接口返回空列表并拒绝写入。提醒订阅、跨项目依赖及对子任务直接设置依赖仍未实现；自动排期已在阶段 5 和工作包 B 中实现，不应再记作阶段 1 缺项。数据库和真实多端验收单独列为发布门槛。

### 阶段 2：里程碑和项目交付概览（P1）

1. 建立项目内里程碑：名称、说明、目标日期、状态、排序和负责人（负责人可选）。
2. 任务可关联里程碑；支持从里程碑视图查看任务、状态分布、未完成数和逾期情况。
3. 甘特图显示里程碑标记，任务列表和筛选器支持按里程碑过滤。
4. 项目页提供交付概览：近期里程碑、风险任务、逾期任务及完成趋势。
5. 里程碑变更写入动态，通知订阅遵循项目权限与个人通知偏好。

**完成条件：** 项目关闭/归档和任务删除后的统计规则明确；时间边界按系统时区统一；里程碑不改变既有工作流完成状态。

**当前进度：** 已实现项目内里程碑增删改查、负责人拖拽排序和可选项目成员负责人、目标日期/状态、任务单里程碑关联、删除时解除任务关联、项目动态记录、负责人/管理员维护权限、任务可见性校验、甘特图日期标记、里程碑关联任务分页清单、工作流状态分布、完成/逾期统计、项目交付摘要、看板/表格/甘特图共用的里程碑筛选、重要变更弱提醒，以及默认关闭、可设当天/提前1/3/7天的目标日期提醒。每分钟后台扫描按项目排期时区在提醒日当地09:00后通过项目群聊投递；失败会持续重试到投递成功或目标日期结束，持久幂等键防止重复消息。负责人仍在项目群时提醒会@负责人，其他群成员静默接收。排序接口会检查项目权限和完整 ID 集合，并与创建/删除操作串行化。提醒为弱提醒，不会强制弹窗；真实投递和多端展示仍待发布验收。

本轮权限审查补齐了五层子任务链上的祖先负责人/显式可见成员访问规则，使里程碑和任务依赖查询与任务列表一致；里程碑解除关联限定在所属项目，并通过项目锁串行化关联与删除。

### 阶段 3：可保存、可复用的任务视图（P2）

1. 在当前筛选/分组基础上增加“保存为视图”，保留状态、负责人、标签、日期、关键词、排序、分组和显示字段。
2. 支持个人视图和项目共享视图；共享视图的创建、编辑、删除权限由项目角色控制。
3. 支持复制、重命名、设为默认、恢复默认；字段不可见或用户无权限时自动降级并提示。
4. 逐步将列表/看板/甘特图的筛选定义统一为同一个可序列化模型，避免各视图筛选结果不一致。
5. 增加常用预设：我的未完成、逾期、本周到期、未排期、被阻塞、近期里程碑。

**当前进度：** 已实现服务端个人/项目共享视图保存、项目成员可见、负责人/管理员共享视图维护权限、用户级默认视图、复制/改名/删除，以及筛选状态、关键词、里程碑、计划日期范围、完成任务开关、视图类型、排序、表格分组和表格字段显示恢复。保存视图时会校验里程碑归属当前项目；日期范围按任务计划区间重叠筛选，无计划日期的任务会排除。表格可独立显示/隐藏列表、优先级、负责人和到期时间。快捷预设包括“我的未完成、逾期、本周到期、未排期、下周到期、近期交付”；近期交付会选择最近的进行中里程碑，应用后可保存为个人或共享视图，其他预设也可保存。应用视图时会展开所选表格分组；失效里程碑筛选会清除并提示。跨端同步及权限降级仍需在发布验收中验证。

**完成条件：** 切换视图不丢失当前工作；跨端同步用户偏好；过期或无权限筛选条件能安全恢复；大项目下筛选保持分页/查询性能。

### 阶段 4：任务模板和批量计划（P2）

1. 完成模板能力盘点后，为模板补齐可复用的层级结构、默认字段、标签、子任务和相对日期。
2. 套用模板时提供预览与选择：全部创建、只选部分子任务、覆盖或保留当前默认值。
3. 支持模板版本/更新时间提示，避免更新模板时悄悄改变已创建任务。
4. 将模板与里程碑连接，支持一次创建项目计划骨架。

**当前进度：** 模板管理支持最多50个子任务节点和5层嵌套，并兼容原有字符串名称格式；每项可选择当前用户或跟随父任务负责人，也可填写相对父任务开始日期的开始/结束偏移。主任务和任意子任务可关联项目里程碑；模板按里程碑名称保存，跨项目套用时在目标项目按名称匹配，缺少对应里程碑则整批任务创建回滚并提示。套用时按父任务负责人和计划时间递归更新子任务，用户手动编辑后保留手动值；新建任务时可全选或只创建部分子任务。模板管理与跨项目预览显示版本号和最近更新时间；内容实际变化时版本递增，新建任务记录来源模板名称和版本，任务保留创建时的内容。模板支持主任务预估工时，套用时填入新建表单且允许修改；工时值进入模板历史快照、版本对比和恢复。模板编辑时会留存不可变历史快照，项目负责人可查看、对比和恢复历史版本；恢复会创建一个新版本并保留恢复前内容，且会核验快照引用的里程碑仍在当前项目内且名称唯一。跨项目模板不保存具体成员 ID。

**完成条件：** 模板跨项目复用受权限控制；重复套用有防重提示；模板修改不会回写已创建任务。

### 阶段 5：排期自动化和时间管理（P2/P3）

1. 在依赖关系稳定后增加自动排期设置：自动/手动模式、工作日历、缓冲天数和排期冲突预览。
2. 日期级联采用预览确认；展示会被移动的任务数量和受影响成员，提供单次撤销/恢复记录。
3. 对计划投入有真实需求的团队，再增加估时、工时记录、剩余工时和进度偏差。
4. 将依赖变化、自动排期结果纳入项目风险视图和提醒，不因普通编辑产生通知噪音。

**当前进度：** 依赖详情会对计划开始早于前置任务计划结束的关系显示冲突提示；甘特图会将当前显示任务的冲突依赖箭头标红并随拖动预览实时更新，未保存计划时间确认表会列出当前任务直接相连且权限可见的冲突依赖，不受搜索或列筛选范围影响。权限查询包含五层内的祖先任务授权。项目现在可配置每周工作日、最多366个具体节假日例外、时区和缓冲工作日，自动排期与容量汇总共用该日历；负责人或管理员可在甘特图预演 FS 后续任务并确认幂等批次应用，也可在日期未被后续改动时撤销。估时、追加式实际工时、历史、容量汇总和 CSV 导出也已实现，具体规则见工作包 B。甘特图已提供项目级依赖风险汇总，可查看当前用户可见的计划冲突和逾期前置任务；风险明细最多50条，计数覆盖全部可见依赖。时区、并发、子任务日期同步及多端行为还需真实环境验证。

**完成条件：** 批量移动可重试且幂等；时区、节假日和非工作日规则可配置；无法移动的手工任务明确标记，不静默覆盖。

### 阶段 6：协作体验和工程演进（P3，持续进行）

1. 统一活动流呈现：字段变化、依赖、里程碑、模板套用和批量排期使用一致的事件格式。
2. 优化任务/项目空状态、加载态、错误恢复和窄屏操作；为桌面、移动网页和 Electron 共用一致的行为规范。
3. 按领域将新增业务规则放入 `app/Services/` 或 `app/Module/`，逐步拆分大型组件的状态和交互，不做大规模重写。
4. 对高流量查询补充索引与分页；搜索同步失败可观测、可重试；后台任务具备锁、幂等和失败记录。
5. 完善 API 行为文档、AI 知识库、语言登记、审计记录和升级说明。

**完成条件：** 新功能可独立维护；日志和错误能定位问题；权限检查集中一致；部署升级失败时有清晰恢复路径。

## 通用验收与发布门槛

- **兼容：** 数据迁移可在现有数据库上升级；旧记录有默认值；至少验证从当前版本连续升级和回滚策略。
- **权限：** 列表、详情、搜索、通知、导出和 WebSocket 推送均遵循同一任务/项目访问规则。
- **体验：** 桌面和移动页面保持可用；异步加载、空结果、失败重试和只读状态清晰。
- **数据一致：** 详情、列表、甘特图、仪表盘、日志和搜索索引对同一任务状态保持一致。
- **工程：** 新控制器保持薄层；业务逻辑有服务层边界；数据库变更有 migration；前端事件和 API 文档同步。
- **帮助内容：** 用户可见功能变动同步更新 `resources/ai-kb/`，并补充中英文语言源。
- **发布：** 先对内部项目或可配置开关试用，再扩大部署；迁移和批量操作提供日志、失败报告和恢复方式。

## 风险和控制措施

| 风险 | 控制措施 |
|---|---|
| 任务关系混淆，旧数据语义改变 | 迁移时将旧关系显式标记为“相关”；新类型分开显示和筛选 |
| 循环依赖导致甘特图/排期失效 | 后端服务层和前端交互均校验，最终以事务内后端校验为准 |
| 跨项目关系泄露数据 | 列表、搜索、通知、日志和跳转统一应用双方权限检查 |
| 自动排期意外移动大量任务 | 分阶段上线，默认不自动级联；先预览、确认、记录和可撤销 |
| 多端筛选行为分叉 | 共用查询定义与序列化格式，建立列表/看板/甘特图的一致性用例 |
| 新功能扩大维护负担 | 先验证团队需求；按领域扩展，避免替换现有 Laravel/Vue 基础架构 |

## 推荐执行顺序

1. 阶段 0 盘点和设计。
2. 阶段 1 依赖关系与甘特图联动，暂不自动移动日期。
3. 阶段 2 里程碑和交付概览。
4. 阶段 3 保存视图。
5. 阶段 4 模板树与批量计划。
6. 阶段 5 自动排期、工时和容量管理（需求验证后）。
7. 阶段 6 持续做协作、性能和架构改进。

此顺序先补任务规划的语义基础，再建立里程碑和可复用视图；自动排期放在依赖关系、工作日规则和撤销机制稳定之后。
