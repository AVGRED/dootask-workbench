# DooTask 发布验收清单

本清单用于把本地工程完成后的外部验收转成可执行记录。它不替代代码审查或备份策略。建议在隔离的预发布环境执行；涉及现有数据的步骤必须先确认备份可恢复。每个门槛都记录执行人、日期、版本、环境、结果和证据链接。失败时记录复现步骤、影响范围、修复版本和重跑结果。

最新本地准备证据见[2026-10-18 WSL 记录](release-evidence/2026-10-18-wsl-local.md)。该记录包含当前提交基线、工具版本、静态检查、隔离 MariaDB 空库升级/最近六条回退重升/独立库 dump 恢复、临时 Redis 双进程锁验证、Nginx/systemd 样例静态检查及部署预检失败项；它不代表任何发布门槛已通过。

## 本地工程验证记录

2026-10-17，本地工作区执行并通过：PHPStan（PHP 8.4，`app/` 全量分析无错误）、`npm run lint`（0 errors，存在既有 warning）、`npm run check:lang`、`npm run check:api-lang`（10 种语言数组与 1,135 条 API 消息一致）、`npm run api:map:check`（24 个控制器/363 个方法）、修改过的 Vue/JS 文件定向 ESLint、`git diff --check` 和 `npx vite build -- fromcmd`（2,904 个模块）。构建产物随后已清理，避免生成的 `public/js/build` 文件进入源码改动。Ubuntu 22.04 WSL 的最近一次 `php artisan dootask:doctor --json` 为 26 项通过、6 项失败（授权库、APP_KEY、数据库与 Redis 未配置/未运行）；完整结果见[当前 Doctor JSON](release-evidence/2026-10-18-doctor-after-seed.json)。较早的 25/7 JSON 在 demo seeder 生成上传目录前执行。2026-10-18 在隔离临时 MariaDB 空库执行全量升级（251 条迁移）、最近六条回退及重升，并使用两条 demo 用户记录完成 dump→独立库恢复；不带 `--step` 回滚整批历史迁移会碰到明确不可逆的数据迁移，因此不作为版本回退方法。完整业务 demo seeder 因授权 FFI 库缺失中断，生成的测试附件暂留在 `public/uploads`。各项命令结果及限制详见[2026-10-18 WSL 记录](release-evidence/2026-10-18-wsl-local.md)。这些本地演练不等同于生产副本恢复、干净主机、多客户端或多实例验收。

2026-10-18 另运行现有自动化用例：完整 PHP Unit suite 在隔离 MariaDB 上 51 项通过、120 assertions；三个 Node 前端单元测试文件 28 项通过，深链目录 21 个 ID 一致。首轮 Node 测试暴露 Windows CRLF 下 `UserSelect` 测试的 import 清理问题，以及项目表格测试仍使用旧 `flowInfo` 形状并漏绑定当前筛选 helper；已更新测试 harness 后重跑通过。最新复核还确认 PHPStan 0 错误、ESLint 0 errors/97 warnings、语言与 API 路由映射检查通过；汇总见 [本地复核记录](release-evidence/2026-10-18-recheck.txt)，PHP 完整 Unit 测试命令与输出见[隔离数据库测试记录](release-evidence/2026-10-18-unit-isolated.txt)。数据库 feature tests、浏览器/Electron 端到端及真实服务场景仍未验收。

在上述记录之后，2026-10-17 又针对跨项目移动时同步全部任务关联的修复重跑本地检查：`composer stan`（PHPStan `app/` 全量分析 0 错误）、`npm run lint`（0 errors、97 warnings）、`npm run check:lang`（阻断错误 0）、`npm run check:api-lang`（1,135 条消息/10 种语言一致）、`npm run api:map:check`（24 个控制器/363 个方法）及 `git diff --check` 均通过。该轮未运行测试套件；警告属于全仓 ESLint 既有告警，需在后续基线治理中单独处理。

随后继续审查移动接口，补上“子任务只能随主任务跨项目移动”的服务端约束，并在跨项目迁移时移除不属于目标项目的子任务成员及指定可见成员；先同步关联再保存子任务，确保异步搜索索引读取到过滤后的权限，最后重同步任务群聊成员。`ProjectTask.php` 的 PHP 语法检查和定向 PHPStan 均通过；新增错误复用既有 API 语言键，API 语言数组检查通过。此轮同样未运行测试套件。

同轮又核对复制与移动 API 的权限对称性：跨项目移动现在也要求目标项目 `TASK_ADD` 权限，和复制接口一致；同项目换列仍只检查 `TASK_MOVE`。此控制器的语法及定向 PHPStan 检查通过。

移动弹窗/API 现仅在位置、状态、负责人和协助人都未变化时视为无操作；同项目同列表下可直接更新状态或成员，且不写入“移动至同项目”的重复动态。PHP 语法、相关前端 ESLint 及定向 PHPStan 检查通过；浏览器交互仍需纳入真实环境验收。

跨项目移动现在也会迁移软删除的子任务和里程碑关系，并保留回收站状态；它们不进入未完成容量计算，之后恢复时仍与父任务同项目。该边界通过静态分析前仍需实际数据库回收站恢复流程验收。

为兼容长期累积的已完成、归档和回收站子任务，迁移用到的树遍历、里程碑、依赖和工时查询均按1000个任务 ID 分块，容量排除列表只包含当前仍计入未完成上限的任务。相关 PHP 语法和定向静态分析稍后复核。

容量检查现将项目总量和目标列表增量分开计算；同列表的状态编辑不会把仍在其他列表的子任务误计入当前列表，换项目/列表时仍按整棵活动子树校验。静态检查待本轮执行。

移动成功后，前端会清除旧子任务缓存并通过递归任务列表接口按用户当前可见性重新加载；根任务也刷新完整详情，避免旧项目成员与工作流状态继续留在本地缓存。需在浏览器覆盖跨项目/换列移动、成员过滤和私有子任务可见性。

继续追查项目专属引用后，跨项目移动会把里程碑按目标项目唯一同名项重新关联（无唯一匹配则解除）；移动树内部的依赖边随项目迁移，连接树外任务的依赖边会删除、记录双方任务动态并在事务提交后更新关系推送。模型和依赖服务的语法检查及定向 PHPStan 均通过；尚未在带项目数据的数据库环境验证移动后的页面和通知行为。

工时历史和容量汇总也会随移动任务改归目标项目。迁移保留软删除幂等墓碑；目标项目出现同成员、同请求号冲突时，迁入记录会得到确定性内部请求号，旧项目摘要清空以便目标项目的首次合法重放重新绑定。跨项目移动按项目 ID 顺序先锁项目再锁任务，和工时写入使用相同的项目/任务锁序；等待锁期间若源项目已变化，则用已登记的 API 提示拒绝过期请求。该逻辑通过 PHP 静态分析，仍需用数据库并发场景验证。

截至本次收口，四个相关 PHP 文件均通过语法检查和定向 PHPStan，全仓 `composer stan` 也以 0 错误通过；API 语言检查扩展至 1,136 条消息/10 种语言并通过，`git diff --check` 通过。没有运行测试套件。

## 2. 现有数据库升级、回退和恢复

在生产同版本的隔离副本执行，记录命令输出和数据库迁移表状态：

本地已使用隔离空库和两条 demo 用户记录做 dump→独立库恢复冒烟，251 条迁移及两条用户摘要匹配；并按 runbook 对 seeder 生成的上传测试文件完成 tar→临时目录恢复和 SHA-256 清单比对。结果见[数据库恢复记录](release-evidence/2026-10-18-db-restore-smoke.txt)和[文件归档记录](release-evidence/2026-10-18-files-archive-smoke.txt)。完整 `DatabaseSeeder` 因缺少授权 FFI 库 `doo.so` 在 WebSocket 对话种子阶段失败，输出见[失败证据](release-evidence/2026-10-18-demo-db-restore.txt)。本地样本不代替下列生产同版本脱敏数据验收；完整业务样本仍需在有授权的隔离环境生成。

1. 生成升级前备份，并恢复到一个全新隔离库；比较关键表行数及抽样业务记录，确认备份可用。
2. 使用目标版本代码在副本执行 `php artisan migrate:status`，保存升级前状态。
3. 在维护窗口内执行 `php artisan migrate --force`，再执行 `php artisan migrate:status`；检查新增索引、外键、旧记录默认值以及依赖/里程碑/视图/排期/工时的读写。
4. 按项目回退说明验证旧应用代码对新 schema 的兼容性。不要假设 `migrate:rollback` 等同于应用版本回滚；记录哪些新增数据不能被旧代码读取。
5. 将升级前备份恢复到独立空库，启动目标版本并复核关键记录和文件引用；记录恢复耗时与丢失窗口。

**通过条件：** 升级完成且旧数据可读写；升级前备份可独立恢复；回退/前向修复路径明确，未发生静默丢数据或权限扩大。

## 3. 干净 Linux 非 Docker 部署与恢复

在没有预装项目文件的干净 Linux VM 上，按 [非 Docker 部署说明](non-docker-deployment.md) 从头安装。记录发行版、内核、PHP/Swoole/LaravelS 版本及所有手工命令。

本地 WSL 已对 runbook 中的 Nginx 片段执行 `nginx -t`，并对 5 个 systemd 单元样例执行 `systemd-analyze verify`；结果和宿主工具告警见[配置语法记录](release-evidence/2026-10-18-config-syntax.txt)。WSL 未启动 systemd 守护进程，因此此项不能替代干净 Linux VM 的部署验收。

- [ ] 以专用低权限系统用户部署，配置生产 `.env`、授权 FFI 库路径和目录权限；确认 `APP_DEBUG=false`、非空 `APP_KEY`、可信主机和 HTTPS 方案。
- [ ] 执行 `php artisan dootask:doctor`；保存输出，并确认其检查结果与实际数据库、Redis、缓存锁、授权库一致。接入自动化时用 `php artisan dootask:doctor --json` 读取结构化结果并依据退出码阻断发布。
- [ ] 执行 `sudo nginx -t`、`sudo systemd-analyze verify /etc/systemd/system/dootask-*.service /etc/systemd/system/dootask-*.timer`；然后按 runbook 启用服务和 timer。
- [ ] 按 runbook 中的实际单元名执行 `systemctl status dootask.service dootask-crontab.service dootask-crontab.timer`、`systemctl list-timers 'dootask-*'` 和 `journalctl -u dootask.service -u dootask-crontab.service`；检查应用日志、计划任务日志和重启策略。
- [ ] 通过 Nginx 验证登录、静态资源、API、文件上传、HTTPS 跳转和 WebSocket；确认 `/health` 存活探针不会被误当成数据库/授权功能检查。
- [ ] 重启主机，验证服务自动恢复、队列继续处理、timer 正常重新调度；停止 Redis/数据库后验证故障可见，恢复依赖后服务可恢复。
- [ ] 按[非 Docker 备份恢复 runbook](non-docker-deployment.md#数据库与文件备份恢复-runbook)用测试数据执行备份与恢复演练，确认文件存储和数据库一致。

**通过条件：** 全新主机可从文档部署；重启后服务和定时器恢复；依赖故障可观测；备份能恢复。WSL 验收不能代替此项。

## 4. WebSocket 授权消息与权限隔离

- [ ] 以有效授权令牌连接 `wss://<host>/ws?action=web&token=<有效令牌>&language=zh&platform=web`，保存握手和客户端日志。
- [ ] 发送一条项目内消息并确认发送方、接收方、持久化记录和实时事件均一致；重复相同幂等请求应只写一条消息、不会重复触发通知。
- [ ] 使用过期/无效令牌和无项目权限账号重试；确认连接或订阅被拒绝，不能收到项目消息、任务细节或隐藏任务更新。
- [ ] 在应用提交成功后模拟 WebSocket 投递失败，再用同一请求 ID 重试；确认状态事件可补投且业务数据/审计/提醒不重复。

**通过条件：** 授权消息往返成功；无权访问被拒绝；重试只补投递，不重复业务副作用。仅拿到 `101 Switching Protocols` 不算通过。

## 5. 多实例共享缓存锁

本地准备阶段已运行 `bash scripts/release-check-redis-lock.sh`，验证两个独立 Laravel PHP 进程对临时 Redis 锁互斥、主动释放后重获，以及持锁进程退出后按 TTL 恢复；最新复核还验证 Redis 不可用时锁操作抛出连接异常、恢复后可重新获取，输出见[Redis 锁与故障恢复记录](release-evidence/2026-10-18-redis-lock-recovery.txt)。这些结果只覆盖同机进程级锁行为；本节所需两份应用实例的提醒/排期业务并发、跨实例日志及已提交批次持久性仍须在预发布环境执行。

- [ ] 启动两份应用实例，确认它们指向同一个 Redis/cache store，使用不同进程和连接。
- [ ] 并发触发相同的里程碑提醒扫描和同一排期批次请求；记录两实例日志、提醒尝试、消息幂等键和排期审计记录。
- [ ] 验证同一时刻只有一个扫描持有者；锁持有者退出后等待 TTL 或释放锁，确认其他实例能接手；确认重复批次请求返回原结果。
- [ ] 断开 Redis 后再恢复，确认错误可观测、不会错误地假定锁已成功，也不会丢失已提交批次。

**通过条件：** 两实例锁互斥且可恢复；并发重试不产生重复批次或提醒。单进程 Redis 锁验证不替代此项。
