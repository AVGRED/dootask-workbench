# 工作台总体设计方案（v2）

重写目标：一套后端、三端前台（员工 / 管理 / 移动），功能全覆盖，可长期加功能。

## 1. 系统全景

```
浏览器 / PWA
   ├── apps/staff    员工端：我的任务、日报、工时、项目
   ├── apps/admin    管理端：组织、权限、项目、报表、系统
   └── apps/mobile   移动端（PWA，复用 staff 组件）
        │  HTTPS / JSON
   └── server（Spring Boot 3，模块化单体）
        ├── MySQL 8.0（沿用旧表 + Flyway 增量）
        ├── Redis（缓存、会话、限流）
        └── 定时任务（周报、提醒、排期）
```

## 2. 后端模块（Maven 多模块，一域一模块）

| 模块 | 职责 | 关键能力 |
|---|---|---|
| `common` | 返回体、异常、分页、审计、幂等 | `{code,message,data,traceId}` |
| `auth` | JWT、登录、验证码、租户无关的会话 | 统一账号，按角色分端 |
| `user` | 用户、部门树、通讯录、导入导出 | 部门负责人视角 |
| `project` | 项目、成员、权限、邀请、移交、设置 | 项目级角色 |
| `task` | 任务、子任务、标签、看板、归档、交接 | 拖动排序、批量操作 |
| `planning` | 依赖、里程碑、自动排期、模板、保存视图 | 预演/应用/撤销 + 幂等批次 |
| `worklog` | 工时、预估、容量汇总 | 93 天上限、可见性 |
| `report` | **日报、周报**、项目报表、账单导出 | 定时汇总 |
| `notify` | 站内消息、WebSocket、提醒 | 可独立成服务 |
| `file` | 上传、预览、附件、WebDAV | 可独立成服务 |
| `ai` | 任务 AI 建议、助手会话 | 可插拔 |
| `ops` | 计时器、徽章、应用中心、系统更新、授权 | 管理端专用 |

## 3. 权限模型

- **RBAC**：角色（系统管理员 / 部门负责人 / 项目经理 / 员工）× 权限点；
- **数据范围**：本人 → 项目成员 → 部门 → 全部，四档；
- **项目级角色**：负责人、管理员、成员、只读；
- 菜单、按钮、API 权限**数据化**，新增功能只配置不改前端路由；
- 后端在 `/api/v1/admin/**` 与 `/api/v1/staff/**` 分命名空间强制校验。

## 4. 数据策略

- 沿用 `dootask` 现有表（`project_tasks`、`project_milestones`、`worklogs` 等），Flyway `V1__baseline.sql` 建表；
- 新功能用新表（如 `daily_reports`、`weekly_summaries`），不改旧表语义；
- 迁移期双读对账：同一查询新旧结果比对，差异记日志；
- 所有时间字段存 UTC，展示按用户时区。

## 5. API 规范

- REST + 版本前缀 `/api/v1`；
- 统一返回 `{code, message, data, traceId}`，错误码集中管理；
- 分页统一 `{list, total, page, size}`；
- OpenAPI 为唯一契约，前端类型自动生成；
- 幂等：写接口支持 `Idempotency-Key`，日报按「用户+日期」天然幂等。

## 6. 前端架构

```
packages/
  ui/      业务组件（按域分目录：task / planning / worklog / report / org）
  api/     OpenAPI 生成的 client + 类型
  auth/    token、权限指令、路由守卫
  mock/    演示数据（离线预览）
apps/
  staff/   员工端
  admin/   管理端
  mobile/  PWA
```

- 状态：Pinia，按域分 store；请求：VueRequest v2（缓存/重试/轮询）；
- 组件规范：单文件组件 ≤ 300 行，超了拆子组件；新组件必须进 `check:vue-wiring` 检查；
- 测试：Vitest + 挂载冒烟（沿用旧项目思路）。

## 7. 核心功能域设计要点

**规划（planning）**
- 依赖：FS 类型、BFS 成环检测、风险汇总；
- 自动排期：预览（不改库）→ 应用（事务 + 幂等批次）→ 撤销（按批次回滚）；
- 里程碑：与任务弱关联，取消关联时批量解绑并留痕；
- 模板：树结构 + 版本历史，恢复即生成新版本。

**工时（worklog）**
- 登记要求 `request_id` 幂等；删除软删；
- 容量汇总：按人聚合预估/已登记/剩余/超出，区间 ≤ 93 天。

**日报 / 周报（report）**
- 日报：每自然日一篇，次日 10:00 后迟交，7 天内可补；
- 周报：周一 02:00 汇总上一自然周，`用户+周` 唯一，重复执行只更新；
- 管理端可按部门查看并标记缺失。

## 8. 非功能要求

| 项 | 目标 |
|---|---|
| 性能 | 列表接口 P95 < 300ms；排期预演 2000 任务 < 3s |
| 可用性 | 单机部署可接受；预留多实例（无本地状态） |
| 可观测 | 结构化日志 + traceId + 慢查询日志 |
| 安全 | 密码 bcrypt、JWT 短期 + 刷新、越权按数据范围校验、上传类型校验 |
| 备份 | MySQL 每日全量 + binlog；文档与配置入 Git |

## 9. 实施阶段

| 阶段 | 内容 | 工期 |
|---|---|---|
| P0 | monorepo、Spring 多模块、Flyway、JWT、OpenAPI、CI、三端可启动 | 1.5 周 |
| P1 | 组织/项目/成员/权限（管理端为主） | 2 周 |
| P2 | 任务/子任务/看板/标签（两端） | 2.5 周 |
| P3 | 依赖/里程碑/自动排期/模板/视图 | 3.5 周 |
| P4 | 工时/容量/甘特/报表 | 2.5 周 |
| P5 | 日报/周报/消息/提醒/附件/审计 | 2.5 周 |
| P6 | 移动端适配、数据迁移对账、灰度切流 | 2 周 |

合计约 **16.5 周**（3 人并行可压到 11–12 周）。

## 10. 风险与对策

- **行为丢失**：以旧系统 316 条 Feature 用例为验收基线，逐条翻译；
- **模块耦合**：只经 Service 接口调用，禁止跨模块访问 Mapper；
- **实时能力**：一期轮询，二期 WebSocket；
- **巨组件回潮**：单文件行数上限 + 连线检查 + 挂载冒烟三道闸；
- **迁移出错**：双读对账 + 灰度 + 旧系统只读保留一个周期。

## 11. 与旧系统的关系

- 旧系统（Laravel + Vue 2）继续维护至新系统通过验收；
- 数据与表结构直接复用，避免重画模型；
- 新功能（日报等）只在新系统实现，旧系统不再加功能。
