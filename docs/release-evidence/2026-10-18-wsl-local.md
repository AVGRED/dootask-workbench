## Redis 锁多进程本地验证

运行 `bash scripts/release-check-redis-lock.sh`。脚本检查测试端口未占用，在 `/tmp` 建立临时目录并启动仅绑定 `127.0.0.1`、关闭 RDB/AOF 持久化的 Redis；再启动两个独立 PHP/Laravel CLI 进程，使用 DooTask 的 Redis cache store 对同一锁竞争。后续复核还加入 Redis 主动停止/恢复场景：停止时锁操作须显式抛出连接异常，重启 Redis 后锁须能重新获取。脚本结束时关闭该 Redis 并删除临时目录；本轮原始输出见[`Redis 锁与故障恢复记录`](2026-10-18-redis-lock-recovery.txt)。

```text
HOLDER_ACQUIRE=PASS
HOLDER_RELEASE=PASS
CONTENDER_BLOCKED=PASS
CONTENDER_ACQUIRE_AFTER_RELEASE=PASS
TTL_HOLDER_ACQUIRE=PASS
TTL_BLOCKED_BEFORE_EXPIRY=PASS
TTL_ACQUIRE_AFTER_EXPIRY=PASS
TWO_PROCESS_SHARED_REDIS_LOCK=PASS
```

这证明同一主机上两个 Laravel 进程通过共享 Redis 实现互斥、主动释放后重获，以及持锁进程退出后在 TTL 前阻塞、过期后重获；另证明 Redis 不可用时操作会显式失败，Redis 恢复后锁可重新获取。不证明两份应用实例的排期/提醒端到端行为、已提交批次的数据持久性或跨主机共享配置。六个发布门槛中的多实例验收仍未完成。
